1 · Recursion & Backtracking

Classes: ADSA 1: Recursion Revision · LAB 1: Recursion & Ad-Hoc

Concepts you need

  • The 3 steps: (1) define what f(args) returns, in words; (2) trust it for smaller input and build the answer for the current input from it; (3) write the base case that stops the recursion.
  • Call stack: every call gets its own frame (own copies of parameters and locals). Statements before the recursive call run on the way down; statements after it run on the way back up, in reverse order.
  • Draw the call tree for any output question. Count nodes for the number of calls, and read the leaves left to right for the order of work.
  • Time = (number of calls) × (work per call). Space = maximum depth of the stack.
  • Common recurrences: T(n)=T(n-1)+1 → O(n); T(n)=T(n/2)+1 → O(log n); T(n)=2T(n-1)+1 → 2n−1 calls; T(n)=2T(n/2)+n → O(n log n); Fibonacci-style f(n-1)+f(n-2) → O(φn) ≈ O(2n).
  • Short-circuit: in a && f(), f() is not called when a is false; in a || f() it is not called when a is true. That ends the recursion early.
  • Nested call f(f(x)): evaluate the inner call fully first, then call f on that result.
  • Accumulator (tail) recursion: pass the partial answer down as a parameter and return it at the base case. Example: reversing digits with acc*10 + n%10.
  • Backtracking template: choose → recurse → un-choose (remove the last element). Copy the list when you save an answer: res.add(new ArrayList<>(cur)).
  • Tree recursion = postorder: get the answers from the left and right subtrees, then combine them at the node. Height counted from the bottom gives "leaf layers".
  • Java stack limit: about 104–105 frames. For a skewed tree with 105 nodes, prefer an iterative version or keep frames small.

Backtracking template

void backtrack(int start, List<Integer> cur, List<List<Integer>> res) {
    if (/* cur is a complete answer */) { res.add(new ArrayList<>(cur)); return; }
    for (int choice = start; choice <= LIMIT; choice++) {
        cur.add(choice);                 // choose
        backtrack(choice + 1, cur, res); // explore (choice+1 => combinations, no reuse)
        cur.remove(cur.size() - 1);      // un-choose
    }
}
Recursion Revision · Q1

Find Leaves of Binary Tree

open on Scaler ↗

Repeatedly peel off all leaves. Return the groups (deepest first, root last), with each group sorted ascending.

Idea

The pass in which a node gets removed is its height from the bottom (leaf = 0, parent = 1 + max(child heights)). So one postorder DFS that puts each node in res[height] gives the answer. No actual removal is needed.

Pointers / traps

  • Sort every group at the end. Values can repeat, so keep duplicates.
  • Return −1 for null so a leaf gets 1 + max(−1,−1) = 0.
  • Add a new list when h == res.size(). Heights come up in increasing order during postorder, so this always works.
Java solution O(n log n) time · O(h) stack
List<List<Integer>> res = new ArrayList<>();
int height(TreeNode n) {
    if (n == null) return -1;
    int h = 1 + Math.max(height(n.left), height(n.right));
    if (h == res.size()) res.add(new ArrayList<>());
    res.get(h).add(n.val);
    return h;
}
public ArrayList<ArrayList<Integer>> solve(TreeNode A) {
    height(A);
    ArrayList<ArrayList<Integer>> ans = new ArrayList<>();
    for (List<Integer> g : res) { Collections.sort(g); ans.add(new ArrayList<>(g)); }
    return ans;
}
Recursion Revision · Q2

Tower of Hanoi

open on Scaler ↗

Move A disks from tower 1 to tower 3. Return every move as [disk, from, to].

Idea

To move n disks from src to dst: move n−1 disks from src to aux, move disk n from src to dst, then move n−1 disks from aux to dst.

Pointers / traps

  • Number of moves = 2A − 1 (A ≤ 18 → 262143 rows).
  • The disk number in a row is n, the parameter of the current call.
  • Argument order matters. The first recursive call is (src → aux using dst) and the second is (aux → dst using src). Check your output against the A = 3 example.
Java solution O(2^n) time · O(n) stack
public int[][] towerOfHanoi(int A) {
    List<int[]> moves = new ArrayList<>();
    hanoi(A, 1, 3, 2, moves);
    return moves.toArray(new int[0][]);
}
void hanoi(int n, int src, int dst, int aux, List<int[]> moves) {
    if (n == 0) return;
    hanoi(n - 1, src, aux, dst, moves);
    moves.add(new int[]{n, src, dst});
    hanoi(n - 1, aux, dst, src, moves);
}

Check Palindrome using Recursion

open on Scaler ↗

Return 1 if string A is a palindrome, else 0, using recursion.

Idea

pal(l, r): if l ≥ r return 1; if the characters differ return 0; otherwise return pal(l+1, r−1).

Pointers / traps

  • Pass indices, not substrings. substring copies the string every call, which makes it O(n²) and fails the time-complexity tests.
  • Depth is |A|/2 ≤ 25000, which Java handles.
  • Base case l >= r covers both odd and even lengths.
Java solution O(n) time · O(n) stack
public int solve(String A) { return pal(A, 0, A.length() - 1); }
int pal(String s, int l, int r) {
    if (l >= r) return 1;
    if (s.charAt(l) != s.charAt(r)) return 0;
    return pal(s, l + 1, r - 1);
}

LAB 1 · Q1

Consecutive Numbers Sum

open on Scaler ↗

Count the ways A (≤ 109) can be written as a sum of consecutive positive integers.

Idea

A sum of k consecutive numbers starting at x is kx + k(k−1)/2 = A. So x = (A − k(k−1)/2) / k must be a positive integer. Try every k while k(k−1)/2 < A, which is about √(2A) ≈ 45000 iterations.

Pointers / traps

  • Use long for k(k−1)/2.
  • k = 1 (A by itself) always counts.
  • Equivalent fact: the answer is the number of odd divisors of A.
Java solution O(√A)
public int solve(int A) {
    int count = 0;
    for (long k = 1; k * (k - 1) / 2 < A; k++)
        if ((A - k * (k - 1) / 2) % k == 0) count++;
    return count;
}
LAB 1 · Q2

Sorted Permutation Rank (distinct chars)

open on Scaler ↗

Find the 1-based rank of string A among all its permutations in sorted order, mod 1000003.

Idea

At position i, every character to the right that is smaller than A[i] could have been placed here instead. Each such choice is followed by (n−1−i)! arrangements, all of which come before A. So rank = 1 + Σ smallerright(i) · (n−1−i)!.

Pointers / traps

  • Precompute factorials mod 1000003 in a long array.
  • Remember the +1 (the rank is 1-based).
  • O(n²) is fine for n ≤ 1000. For larger n, count with a frequency array (see the version with repeats).
Java solution O(n²)
public int findRank(String A) {
    final int M = 1000003;
    int n = A.length();
    long[] fact = new long[n + 1];
    fact[0] = 1;
    for (int i = 1; i <= n; i++) fact[i] = fact[i - 1] * i % M;
    long rank = 0;
    for (int i = 0; i < n; i++) {
        int smaller = 0;
        for (int j = i + 1; j < n; j++) if (A.charAt(j) < A.charAt(i)) smaller++;
        rank = (rank + smaller * fact[n - 1 - i]) % M;
    }
    return (int) ((rank + 1) % M);
}

Combinations

open on Scaler ↗

Return all combinations of B numbers chosen from 1..A, in sorted order.

Idea

Backtracking where each call picks the next number from start..A. Recursing with i+1 keeps every entry increasing, and looping in increasing order makes the list of entries sorted.

Pointers / traps

  • Copy the list when saving: new ArrayList<>(cur).
  • Optional pruning: stop the loop when A − i + 1 < B − cur.size().
  • Do not use library functions (the statement forbids it).
Java solution O(C(A,B)·B)
public ArrayList<ArrayList<Integer>> combine(int A, int B) {
    ArrayList<ArrayList<Integer>> res = new ArrayList<>();
    go(1, A, B, new ArrayList<>(), res);
    return res;
}
void go(int start, int A, int B, ArrayList<Integer> cur, ArrayList<ArrayList<Integer>> res) {
    if (cur.size() == B) { res.add(new ArrayList<>(cur)); return; }
    for (int i = start; i <= A; i++) {
        cur.add(i);
        go(i + 1, A, B, cur, res);
        cur.remove(cur.size() - 1);
    }
}

Print 1..n vs n..1: print after the recursive call → 1..n (the lecture example check(n-1); print(n)); print before it → n..1.
Power an recursively in O(log n): compute half = pow(a, n/2), square it, and multiply by a once more if n is odd. Calls only pow(n/2) once. Calling it twice makes it O(n) again.
code
long pow(long a, long n, long m) {
    if (n == 0) return 1 % m;
    long half = pow(a, n / 2, m);
    long res = half * half % m;
    return n % 2 == 1 ? res * (a % m) % m : res;
}
All subsets (power set): for each element, either take it or skip it. That gives 2n leaves.
code
void subsets(int[] a, int i, List<Integer> cur, List<List<Integer>> res) {
    if (i == a.length) { res.add(new ArrayList<>(cur)); return; }
    cur.add(a[i]);
    subsets(a, i + 1, cur, res);          // take
    cur.remove(cur.size() - 1);
    subsets(a, i + 1, cur, res);          // skip
}
All permutations (distinct): use a used[] array, try every unused element at each position, and backtrack. That gives n! leaves.
code
void permute(int[] a, boolean[] used, List<Integer> cur, List<List<Integer>> res) {
    if (cur.size() == a.length) { res.add(new ArrayList<>(cur)); return; }
    for (int i = 0; i < a.length; i++) {
        if (used[i]) continue;
        used[i] = true; cur.add(a[i]);
        permute(a, used, cur, res);
        used[i] = false; cur.remove(cur.size() - 1);
    }
}
Sum of digits / count digits / reverse: use n % 10 for the last digit and recurse on n / 10. Base case n == 0.
Height of a binary tree: h(null) = -1 (edges) or 0 (nodes); h(n) = 1 + max(h(l), h(r)). This is the same recursion as Find Leaves.

Concepts you need

  • Rule of sum: when you do one task OR another, add the counts. Rule of product: when you do one AND then another, multiply the counts.
  • Permutations nPr = n!/(n−r)! (order matters). Combinations nCr = n!/(r!(n−r)!) (order does not matter).
  • Pascal's identity: nCr = (n−1)C(r−1) + (n−1)Cr (either element n is chosen or it is not). Base cases: nC0 = nCn = 1. This needs only addition, so it works with any modulus m.
  • Symmetry: nCr = nC(n−r). Row sum: Σ nCr = 2n, which is the number of subsets.
  • Arrangements with repeats: n! / (f₁! · f₂! · …).
  • Grid paths (moving only right/down): you make (A−1) downs and (B−1) rights in some order, so paths = C(A+B−2, A−1).
  • Independent choices per group: if group g can be used in cg ways or skipped, the total is Π(1 + cg). Subtract 1 to drop the "skip everything" (empty) case.
  • Lexicographic rank: for each position, count the strings that start with a smaller character at that position and match everything before it. Add 1 at the end.
  • Excel columns are base 26 without a zero digit (A = 1 … Z = 26). Going number → title, do A-- before each % 26.
Combinatorics · Q1

Count Good Subsequences

open on Scaler ↗

Count the non-empty subsequences (as sets of indices) in which every distinct value appears the same number of times, mod 109+7.

Idea

Fix the common frequency k. Each distinct value v with frequency fv is either left out (1 way) or included exactly k times (C(fv, k) ways). So countk = Πv(1 + C(fv, k)) − 1, where the −1 removes the empty choice. The answer is Σk=1..maxF countk.

Pointers / traps

  • For a given k, only values with fv ≥ k contribute a factor other than 1. Sort the frequencies in descending order and break early. The total work is Σ fv = n, so this is O(n).
  • Precompute fact and invFact up to n (Fermat inverse, see section 3).
  • Use (prod − 1 + MOD) % MOD to avoid a negative result.
  • Check: [1,2,1] → k=1: (1+2)(1+1)−1 = 5; k=2: (1+1)(1+0)−1 = 1; total 6 ✓
Java solution O(n log n)
static final long MOD = 1_000_000_007L;
public int solve(int[] A) {
    int n = A.length;
    long[] fact = new long[n + 1], invFact = new long[n + 1];
    fact[0] = 1;
    for (int i = 1; i <= n; i++) fact[i] = fact[i - 1] * i % MOD;
    invFact[n] = power(fact[n], MOD - 2, MOD);
    for (int i = n; i > 0; i--) invFact[i - 1] = invFact[i] * i % MOD;

    HashMap<Integer, Integer> freq = new HashMap<>();
    for (int x : A) freq.merge(x, 1, Integer::sum);
    List<Integer> fs = new ArrayList<>(freq.values());
    fs.sort(Collections.reverseOrder());

    long ans = 0;
    for (int k = 1; k <= fs.get(0); k++) {
        long prod = 1;
        for (int f : fs) {
            if (f < k) break;
            long c = fact[f] * invFact[k] % MOD * invFact[f - k] % MOD;
            prod = prod * (1 + c) % MOD;
        }
        ans = (ans + prod - 1 + MOD) % MOD;
    }
    return (int) ans;
}
Combinatorics · Q2

Compute nCr % m (m NOT prime)

open on Scaler ↗

Return nCr % m, with A·B ≤ 106 and m ≤ 106 (any m, not necessarily prime).

Idea

m might not be prime, so modular inverses may not exist and the factorial formula cannot be used. Use Pascal's identity (only additions) with a 1-D row of size r+1, updated right-to-left. Cost O(n·r) ≤ 106.

Pointers / traps

  • Update j from high to low so C[j-1] still holds the previous row's value.
  • Start with C[0] = 1 % m (gives 0 when m = 1).
  • The constraint A·B ≤ 106 is the hint that O(n·r) is intended.
Java solution O(n·r) time · O(r) space
public int solve(int A, int B, int C) {
    long[] dp = new long[B + 1];
    dp[0] = 1 % C;
    for (int i = 1; i <= A; i++)
        for (int j = Math.min(i, B); j > 0; j--)
            dp[j] = (dp[j] + dp[j - 1]) % C;
    return (int) dp[B];
}
Combinatorics · Q3

Grid Unique Paths

open on Scaler ↗

Count the paths from the top-left to the bottom-right of an A × B grid, moving only right or down.

Idea

Every path is some ordering of (A−1) D's and (B−1) R's, so the answer is C(A+B−2, A−1). Compute it as a running product res = res · (n−r+i) / i. Each intermediate value is itself a binomial coefficient, so the division is always exact.

Pointers / traps

  • Use long for res and take r = min(A,B) − 1.
  • Multiply before dividing.
  • DP alternative: dp[i][j] = dp[i−1][j] + dp[i][j−1].
Java solution O(min(A,B))
public int uniquePaths(int A, int B) {
    long res = 1;
    int n = A + B - 2, r = Math.min(A, B) - 1;
    for (int i = 1; i <= r; i++) res = res * (n - r + i) / i;
    return (int) res;
}

Pascal Triangle

open on Scaler ↗

Return an A × A matrix whose row i holds iC0 … iCi, padded with 0s.

Idea

t[i][0] = 1 and t[i][j] = t[i−1][j−1] + t[i−1][j]. Java zero-fills new arrays, so the padding is already there.

Pointers / traps

  • The output is A × A including the zeros, not a jagged array.
  • A ≤ 25, so the values fit in an int (24C12 = 2704156).
Java solution O(A²)
public int[][] solve(int A) {
    int[][] t = new int[A][A];
    for (int i = 0; i < A; i++) {
        t[i][0] = 1;
        for (int j = 1; j <= i; j++) t[i][j] = t[i - 1][j - 1] + t[i - 1][j];
    }
    return t;
}

LAB 2 · Q2

Sorted Permutation Rank with Repeats

open on Scaler ↗

Find the rank among the unique permutations, with |A| ≤ 106, mod 1000003 (prime). Compare characters by ASCII value (uppercase sorts before lowercase).

Idea

At position i, placing a smaller character c there leaves (n−1−i)! / Π freq! arrangements, where c's count is reduced by 1. Since 1/(f−1)! = f · 1/f!, the contribution of all smaller characters together is (n−1−i)! · invProd · Σc<A[i] freq[c], where invProd = 1/Π freq[c]! over the remaining characters. After processing position i, remove A[i]: invProd *= freq[A[i]]; freq[A[i]]--.

Pointers / traps

  • Here 1000003 is prime and n < 1000003, so every factorial is invertible and Fermat works.
  • Use a 256-size frequency array (ASCII order handles upper/lower case).
  • Do not recompute the denominator from scratch at each position (O(n·256·log) is too slow). Update invProd as you go.
  • Remember the final +1.
Java solution O(256·n)
public int findRank(String A) {
    final long M = 1000003;
    int n = A.length();
    long[] fact = new long[n + 1];
    fact[0] = 1;
    for (int i = 1; i <= n; i++) fact[i] = fact[i - 1] * i % M;
    int[] freq = new int[256];
    for (char c : A.toCharArray()) freq[c]++;
    long invProd = 1;                                   // 1 / Π freq[c]!
    for (int c = 0; c < 256; c++) invProd = invProd * power(fact[freq[c]], M - 2, M) % M;
    long rank = 0;
    for (int i = 0; i < n; i++) {
        char ch = A.charAt(i);
        long smaller = 0;
        for (int c = 0; c < ch; c++) smaller += freq[c];
        rank = (rank + fact[n - 1 - i] * invProd % M * (smaller % M)) % M;
        invProd = invProd * freq[ch] % M;               // drop one ch: 1/(f-1)! = f/f!
        freq[ch]--;
    }
    return (int) ((rank + 1) % M);
}

Yet another MATRIX question

open on Scaler ↗

An A × B matrix of 1s. Count the ways to flip cells to −1 so that every column sums to 0, mod 109+7.

Idea

Columns are independent of each other. A column sums to 0 only when exactly A/2 of its cells are flipped, so each column has C(A, A/2) choices if A is even and 0 if A is odd. The answer is C(A, A/2)B mod p.

Pointers / traps

  • If A is odd, return 0.
  • Compute C(A, A/2) mod p with factorials and Fermat (or Pascal, since A ≤ 1000), then use fast power for ^B.
  • Rows do not matter. The constraint is only on columns.
Java solution O(A + log B)
public int solve(int A, int B) {
    if (A % 2 == 1) return 0;
    long num = 1, den = 1;
    for (int i = 1; i <= A; i++) num = num * i % MOD;
    for (int i = 1; i <= A / 2; i++) den = den * i % MOD;
    long c = num * power(den * den % MOD, MOD - 2, MOD) % MOD;   // C(A, A/2)
    return (int) power(c, B, MOD);
}

3 · Modular arithmetic & Fermat's theorem

Classes: ADSA 1: Fermat Theorem · LAB 2: Maths Ad-Hoc

Concepts you need

  • Congruence: a ≡ b (mod m) means a and b leave the same remainder mod m, i.e. m divides (a − b). Example: 10 ≡ 15 (mod 5).
  • Modular inverse of a (mod m) is the x with a·x ≡ 1 (mod m).
  • Mod rules: (a+b)%m, (a·b)%m = ((a%m)·(b%m))%m, (a−b)%m = ((a−b)%m + m)%m. Division does not work this way: multiply by the modular inverse instead.
  • Overflow: two values below 109+7 multiply to about 1018, which fits in a long (max ≈ 9.2·1018) but not an int. Cast to long before multiplying: (long) a * b % MOD.
  • Fast exponentiation: ab in O(log b) by squaring a and multiplying it into the result whenever the current bit of b is 1.
  • Fermat's little theorem: if p is prime and p ∤ a, then ap−1 ≡ 1 (mod p). Two consequences:
  •   → Inverse: a−1 ≡ ap−2 (mod p).
  •   → Reducing a huge exponent: ae ≡ ae mod (p−1) (mod p). The exponent is reduced mod p−1, not p.
  • An inverse exists only when gcd(a, m) = 1. If m is not prime, Fermat does not apply: use Pascal DP or the extended Euclid algorithm.
  • Choosing an nCr method: small n·r with any m → Pascal DP · n ≤ 106 with a prime p > n → factorials + Fermat · many queries → precompute fact[] and invFact[] · p prime but small (p ≤ n) → Lucas' theorem.
  • gcd / lcm: gcd(a,b) = gcd(b, a%b); lcm = a / gcd · b (divide first to avoid overflow).
  • Inclusion–exclusion: the count of numbers ≤ x divisible by B or C is x/B + x/C − x/lcm(B,C).
  • Binary search on the answer: when count(x) is monotonic, find the smallest x with count(x) ≥ A.

Templates to know by heart

static final long MOD = 1_000_000_007L;

static long power(long a, long b, long m) {          // a^b % m, O(log b)
    long res = 1 % m; a %= m;
    while (b > 0) {
        if ((b & 1) == 1) res = res * a % m;
        a = a * a % m;
        b >>= 1;
    }
    return res;
}
static long inv(long a, long p) { return power(a, p - 2, p); }   // p prime, gcd(a,p)=1

// nCr for many queries, p prime > N
long[] fact = new long[N + 1], invFact = new long[N + 1];
fact[0] = 1;
for (int i = 1; i <= N; i++) fact[i] = fact[i - 1] * i % MOD;
invFact[N] = inv(fact[N], MOD);
for (int i = N; i > 0; i--) invFact[i - 1] = invFact[i] * i % MOD;   // only ONE power() call
long nCr(int n, int r) { return r < 0 || r > n ? 0 : fact[n] * invFact[r] % MOD * invFact[n - r] % MOD; }

static long gcd(long a, long b) { return b == 0 ? a : gcd(b, a % b); }

Convert a number (≤ 109) to its Excel column title: 27 → "AA".

Idea

This is base 26 with digits 1..26 instead of 0..25. Decrement before each step: A--; digit = A % 26; A /= 26;. Build the string and reverse it.

Pointers / traps

public String convertToTitle(int A) {
    StringBuilder sb = new StringBuilder();
    while (A > 0) {
        A--;
        sb.append((char) ('A' + A % 26));
        A /= 26;
    }
    return sb.reverse().toString();
}
Fermat · Q2

Very Large Power: A^(B!) mod 1e9+7

open on Scaler ↗

Compute AB! mod (109+7) for A, B ≤ 5·105.

Idea

B! is far too large to compute directly. By Fermat, the exponent can be reduced mod (p−1): e = B! mod (109+6), then the answer is power(A, e, p).

Pointers / traps

  • The exponent is taken mod p−1 = 1000000006, not p. This is the most common mistake on this problem.
  • It works because A ≤ 5·105 is never a multiple of p.
  • Edge case from the lecture: if B! ≡ 0 (mod p−1), the answer is A0 = 1. Example: A = 3, B = 5, p = 11 → 120 mod 10 = 0 → 1. This is correct, not a bug.
  • Alternative that avoids Fermat: ans = A; for i in 2..B: ans = power(ans, i), since AB! = (((A2)3)4…). It is O(B log B) and also passes.
Java solution O(B + log p)
public int solve(int A, int B) {
    long e = 1;
    for (int i = 2; i <= B; i++) e = e * i % (MOD - 1);   // B! mod (p-1)
    return (int) power(A, e, MOD);
}
Fermat · Q3

Compute nCr % p (p prime ≥ n)

open on Scaler ↗

Return nCr mod p, where n ≤ 106 and p is prime with p ≥ n ("1 counts as prime" here).

Idea

n! · inv(r!) · inv((n−r)!) mod p, with inverses from Fermat (xp−2). Valid because r! and (n−r)! contain no factor of p when r and n−r are below p.

Pointers / traps

  • p = 1: return 0 (anything mod 1 is 0).
  • r = n (and possibly p = n): return 1 directly. Otherwise, with p = n, n! ≡ 0 and the formula would wrongly give 0.
  • Use long throughout. Computing the product incrementally avoids building an array of size 106.
Java solution O(n + log p)
public int solve(int A, int B, int C) {          // A = n, B = r, C = p
    if (C == 1) return 0;
    if (B == A) return 1;
    long num = 1, den = 1;
    for (int i = 1; i <= A; i++) num = num * i % C;
    for (int i = 1; i <= B; i++) den = den * i % C;
    for (int i = 1; i <= A - B; i++) den = den * i % C;
    return (int) (num * power(den, C - 2, C) % C);
}

LAB 2 · Q3

Ath Magical Number

open on Scaler ↗

A number is magical if B or C divides it. Return the A-th smallest magical number (A ≤ 109), mod 109+7.

Idea

count(x) = x/B + x/C − x/lcm(B,C) is non-decreasing in x. Binary search for the smallest x with count(x) ≥ A, in the range [min(B,C), A·min(B,C)].

Pointers / traps

  • The answer can reach about 4·1013, so everything must be long (lo, hi, mid, lcm).
  • Apply the mod only to the final answer. Taking mod inside the search breaks the ordering the search relies on.
  • Compute lcm as B / gcd · C. Forgetting to subtract the lcm term double-counts multiples of both.
Java solution O(log(A·min(B,C)))
public int solve(int A, int B, int C) {
    long lcm = (long) B / gcd(B, C) * C;
    long lo = Math.min(B, C), hi = (long) A * Math.min(B, C), ans = hi;
    while (lo <= hi) {
        long mid = lo + (hi - lo) / 2;
        long cnt = mid / B + mid / C - mid / lcm;
        if (cnt >= A) { ans = mid; hi = mid - 1; }
        else lo = mid + 1;
    }
    return (int) (ans % 1_000_000_007L);
}

4 · Binary Search Trees

Classes: ADSA 1: BST 1 · BST 2 · BST 3 · LAB 3: BST

Concepts you need

  • Terms: root (topmost node), leaf (no children), parent/child, siblings (same parent), height (longest root-to-leaf path).
  • Where BSTs are used (from BST 1): AVL tree = strictly balanced BST, always O(log n) height · Red-Black tree = slightly relaxed self-balancing BST, used by Java's TreeMap/TreeSet · B+ tree = multi-way search tree used in databases and file systems for disk indexing.
  • Insert: follow the search path and attach the new node at the first null child. Duplicates: decide up front whether they go left or right. Min = keep going left, max = keep going right.
  • Height decides speed: inserting already-sorted data makes a skewed tree (a linked list), so h = n and every operation is O(n). Building from the middle of a sorted array keeps h = log n.
  • BST property: every node in the left subtree is less than the node, and every node in the right subtree is greater. Comparing only with direct children is not enough.
  • Inorder traversal of a BST is sorted. Most BST problems reduce to "process the sorted sequence" (k-th smallest, two-sum, merging two BSTs, validation).
  • Search / insert / delete take O(h): h = log n when balanced and n when skewed. Go left if the key is smaller than the node, otherwise go right. These loops can be iterative, so they need no stack.
  • Validate with a range: pass (lo, hi) down the tree. The left child gets (lo, node), the right child gets (node, hi). Use long bounds.
  • Delete has 3 cases: leaf → return null; one child → return that child; two children → copy in the in-order predecessor (max of the left subtree, as this assignment asks) or successor (min of the right), then delete that node from its subtree.
  • Predecessor = rightmost node of the left subtree. Successor = leftmost node of the right subtree.
  • Balanced BST from sorted data: the middle element becomes the root; recurse on both halves.
  • Range pruning: if node < low, only the right subtree can contain answers; if node > high, only the left.
  • BST iterator (a stack of left-spine nodes) gives the next inorder value in amortised O(1) with O(h) memory. Running one forward and one reverse iterator gives two pointers on a BST.
  • Morris traversal does an inorder walk with O(1) extra space by temporarily linking each predecessor's right pointer back to the current node.
  • Bottom-up info (postorder): return a tuple such as {{isBST, size, min, max}} from each subtree and combine at the parent. This is O(n) instead of O(n²).

Deque<TreeNode> st = new ArrayDeque<>();

Sorted Array To Balanced BST

open on Scaler ↗

Build a height-balanced BST from a sorted array.

Idea

Root = a[mid]. Build the left subtree from a[l..mid−1] and the right subtree from a[mid+1..r].

Pointers / traps

  • mid = l + (r−l)/2. Any balanced answer should be accepted: the sample output itself is not consistent about lower vs upper middle.
  • Recursion depth is log n, so it is safe.
  • Pass indices instead of copying subarrays.
Java solution O(n)
public TreeNode sortedArrayToBST(final int[] A) { return build(A, 0, A.length - 1); }
TreeNode build(int[] a, int l, int r) {
    if (l > r) return null;
    int mid = l + (r - l) / 2;
    TreeNode root = new TreeNode(a[mid]);
    root.left = build(a, l, mid - 1);
    root.right = build(a, mid + 1, r);
    return root;
}
BST 1 · Q2

Check for BST with One Child

open on Scaler ↗

Given a preorder sequence, could it come from a BST in which every internal node has exactly one child? Answer YES or NO.

Idea

With one child per node, the tree is a single path, so each next element must go left or right of the current one and stay inside every bound set so far. Keep a window (lo, hi). If the next element is greater than the current, the path turns right, so set lo = current; otherwise hi = current. Every next element must lie strictly inside (lo, hi).

Pointers / traps

  • Equivalent check: for every i, all later elements are either all greater or all smaller than A[i]. You can test this with suffix min/max.
  • Use long sentinels for the initial lo and hi.
  • Check: [1,5,6,4] → after 5→6, lo = 5, but 4 < 5, so NO.
Java solution O(n) · O(1)
public String solve(int[] A) {
    long lo = Long.MIN_VALUE, hi = Long.MAX_VALUE;
    for (int i = 0; i + 1 < A.length; i++) {
        if (A[i + 1] > A[i]) lo = A[i]; else hi = A[i];
        if (A[i + 1] <= lo || A[i + 1] >= hi) return "NO";
    }
    return "YES";
}

Insert, Min & Max in a BST

taught in lecture (no assignment problem)

Taught in BST 1 (no assignment problem). Insert value x, and find the minimum and maximum.

Idea

Insert: go left if x is smaller, otherwise right, and attach x where you reach null. Assign the returned subtree back to the parent's pointer. Min: the leftmost node. Max: the rightmost node.

Pointers / traps

  • The duplicate rule here sends equal values to the right. Pick one rule and keep it.
  • Min/max on an empty tree: check root == null first.
  • Insert is O(h): O(log n) when balanced, O(n) when skewed (e.g. sorted input).
Java solution O(h)
TreeNode insert(TreeNode root, int x) {
    if (root == null) return new TreeNode(x);
    if (x < root.val) root.left = insert(root.left, x);
    else root.right = insert(root.right, x);
    return root;
}
int min(TreeNode r) { while (r.left != null) r = r.left; return r.val; }
int max(TreeNode r) { while (r.right != null) r = r.right; return r.val; }

Valid Binary Search Tree

open on Scaler ↗

Check whether a binary tree is a BST (strict: left < node < right).

Idea

Recurse with an allowed range: valid(n, lo, hi) requires lo < n.val < hi. The left child gets (lo, n.val) and the right child gets (n.val, hi).

Pointers / traps

  • The classic mistake is comparing a node only with its direct children. A deeper node can still break the rule for an ancestor.
  • Node values go up to 232−1, so use long bounds.
  • Alternative: do an inorder traversal and check that it is strictly increasing.
Java solution O(n)
public int isValidBST(TreeNode A) { return valid(A, Long.MIN_VALUE, Long.MAX_VALUE) ? 1 : 0; }
boolean valid(TreeNode n, long lo, long hi) {
    if (n == null) return true;
    if (n.val <= lo || n.val >= hi) return false;
    return valid(n.left, lo, n.val) && valid(n.right, n.val, hi);
}
BST 2 · lecture

Valid BST: bottom-up method

taught in lecture (no assignment problem)

The second correct method from the BST 2 lecture. The lecture also showed that checking only the immediate children is wrong.

Idea

Postorder: each subtree reports its {min, max}. The node is valid when left.max < node < right.min and both subtrees are valid. Return null as soon as any subtree fails.

Pointers / traps

  • Why the children-only check fails: in 10 → (5, 15 → (6, 20)), 6 < 15 is fine locally, but 6 is in the right subtree of 10.
  • An empty subtree returns {+∞, −∞} so that any value passes.
  • Top-down (range) and bottom-up are both O(n). Use whichever you remember better.
Java solution O(n)
long[] check(TreeNode n) {                    // {min, max}, or null if not a BST
    if (n == null) return new long[]{Long.MAX_VALUE, Long.MIN_VALUE};
    long[] L = check(n.left);
    if (L == null) return null;
    long[] R = check(n.right);
    if (R == null) return null;
    if (L[1] >= n.val || R[0] <= n.val) return null;
    return new long[]{Math.min(L[0], n.val), Math.max(R[1], n.val)};
}
public int isValidBST(TreeNode A) { return check(A) != null ? 1 : 0; }
BST 2 · Q2

Largest BST Subtree

open on Scaler ↗

Return the size of the largest subtree that is a BST.

Idea

Postorder: each subtree returns {isBST, size, min, max}. A node forms a BST when both children are BSTs and left.max < node < right.min. Track the best size seen.

Pointers / traps

  • An empty subtree returns {true, 0, +∞, −∞}, so a leaf passes the check automatically.
  • When a subtree is not a BST, its parent cannot be one either. Return isBST = false.
  • Checking validity separately at each node is O(n²). Returning the tuple makes it O(n).
Java solution O(n)
int best = 0;
public int solve(TreeNode A) { best = 0; go(A); return best; }
long[] go(TreeNode n) {                       // {isBST, size, min, max}
    if (n == null) return new long[]{1, 0, Long.MAX_VALUE, Long.MIN_VALUE};
    long[] L = go(n.left), R = go(n.right);
    if (L[0] == 1 && R[0] == 1 && L[3] < n.val && n.val < R[2]) {
        long size = L[1] + R[1] + 1;
        best = (int) Math.max(best, size);
        return new long[]{1, size, Math.min(L[2], n.val), Math.max(R[3], n.val)};
    }
    return new long[]{0, 0, 0, 0};
}
BST 2 · Q3

Delete a node in BST

open on Scaler ↗

Delete value B. When the node has two children, replace it with its in-order predecessor.

Idea

Search recursively, re-attaching the returned child at each step. At the target: no left child → return the right; no right child → return the left; two children → copy the predecessor's value (max of the left subtree) and delete that value from the left subtree.

Pointers / traps

  • The problem says predecessor (max of the left subtree), not successor. Using the successor gives a different tree and a wrong answer.
  • Always assign the result back: root.left = delete(root.left, …).
  • If B is not in the tree, return the tree unchanged.
Java solution O(h)
public TreeNode solve(TreeNode root, int B) {
    if (root == null) return null;
    if (B < root.val) root.left = solve(root.left, B);
    else if (B > root.val) root.right = solve(root.right, B);
    else {
        if (root.left == null) return root.right;
        if (root.right == null) return root.left;
        TreeNode pred = root.left;
        while (pred.right != null) pred = pred.right;
        root.val = pred.val;
        root.left = solve(root.left, pred.val);
    }
    return root;
}

Kth Smallest Element In BST

open on Scaler ↗

Return the B-th smallest value.

Idea

Do an iterative inorder traversal and count the nodes visited. Stop at the B-th one.

Pointers / traps

  • Stopping early makes it O(h + B), not O(n).
  • Morris traversal also works if you need O(1) space.
Java solution O(h + B)
public int kthsmallest(TreeNode A, int B) {
    Deque<TreeNode> st = new ArrayDeque<>();
    TreeNode cur = A;
    while (cur != null || !st.isEmpty()) {
        while (cur != null) { st.push(cur); cur = cur.left; }
        cur = st.pop();
        if (--B == 0) return cur.val;
        cur = cur.right;
    }
    return -1;
}
BST 3 · lecture

Kth smallest with Morris (O(1) space)

taught in lecture (no assignment problem)

The BST 3 lecture combined both ideas: count nodes during a Morris inorder traversal.

Idea

Use the same Morris loop as below. Increase the count at the two places where a node is visited; the k-th visited node is the answer.

Pointers / traps

  • Let the loop finish instead of returning early. Otherwise some threads stay in the tree and it remains modified.
  • O(n) time, O(1) extra space.
Java solution O(n) · O(1)
public int kthsmallest(TreeNode root, int k) {
    TreeNode cur = root;
    int count = 0, ans = -1;
    while (cur != null) {
        if (cur.left == null) {
            if (++count == k) ans = cur.val;
            cur = cur.right;
        } else {
            TreeNode pre = cur.left;
            while (pre.right != null && pre.right != cur) pre = pre.right;
            if (pre.right == null) { pre.right = cur; cur = cur.left; }
            else {
                pre.right = null;
                if (++count == k) ans = cur.val;
                cur = cur.right;
            }
        }
    }
    return ans;
}
BST 3 · Q2

Path to Given Node

open on Scaler ↗

Binary tree (not a BST) with unique values: return the path from the root to node B.

Idea

DFS with a path list: add the node, return true if it is B or if B is found in either subtree, otherwise remove the node (backtrack) and return false.

Pointers / traps

  • This is not a BST, so you cannot choose a direction. Search both sides.
  • Use short-circuit || so the search stops as soon as B is found.
  • Variation: the path between two nodes = the common prefix of their two root paths, then the two remaining tails.
Java solution O(n)
public int[] solve(TreeNode A, int B) {
    List<Integer> p = new ArrayList<>();
    find(A, B, p);
    return p.stream().mapToInt(i -> i).toArray();
}
boolean find(TreeNode n, int B, List<Integer> p) {
    if (n == null) return false;
    p.add(n.val);
    if (n.val == B || find(n.left, B, p) || find(n.right, B, p)) return true;
    p.remove(p.size() - 1);
    return false;
}
BST 3 · Q3

Morris Inorder Traversal

open on Scaler ↗

Return the inorder traversal without using recursion or a stack.

Idea

At cur: if there is no left child, visit cur and go right. Otherwise find the predecessor (the rightmost node of the left subtree). If its right pointer is null, set it to cur (a thread) and go left. If it already points to cur, the left subtree is done: remove the thread, visit cur, and go right.

Pointers / traps

  • The inner loop must check pre.right != cur, or it will follow the thread forever.
  • Remove every thread so the tree is restored afterwards.
  • For preorder Morris, visit cur when you create the thread instead.
Java solution O(n) time · O(1) space
public int[] solve(TreeNode A) {
    List<Integer> res = new ArrayList<>();
    TreeNode cur = A;
    while (cur != null) {
        if (cur.left == null) { res.add(cur.val); cur = cur.right; }
        else {
            TreeNode pre = cur.left;
            while (pre.right != null && pre.right != cur) pre = pre.right;
            if (pre.right == null) { pre.right = cur; cur = cur.left; }          // thread + go left
            else { pre.right = null; res.add(cur.val); cur = cur.right; }        // unthread + visit
        }
    }
    return res.stream().mapToInt(i -> i).toArray();
}
LAB 3 · Q1

Two Sum BST

open on Scaler ↗

Do two different nodes have values that add up to B?

Idea

Two pointers over the sorted order: a forward inorder iterator (smallest first) and a reverse one (largest first). If the sum is less than B, advance the forward iterator; if greater, advance the reverse one; stop when they reach the same node.

Pointers / traps

  • The loop condition lo.peek() != hi.peek() prevents using the same node twice.
  • Simpler O(n)-space option: a HashSet during a traversal, checking set.contains(B − v) before adding v.
  • Use long for the sum to be safe.
Java solution O(n) time · O(h) space
public int t2Sum(TreeNode A, int B) {
    Deque<TreeNode> lo = new ArrayDeque<>(), hi = new ArrayDeque<>();
    for (TreeNode c = A; c != null; c = c.left) lo.push(c);
    for (TreeNode c = A; c != null; c = c.right) hi.push(c);
    while (!lo.isEmpty() && !hi.isEmpty() && lo.peek() != hi.peek()) {
        long s = (long) lo.peek().val + hi.peek().val;
        if (s == B) return 1;
        if (s < B) { TreeNode c = lo.pop().right; for (; c != null; c = c.left) lo.push(c); }
        else       { TreeNode c = hi.pop().left;  for (; c != null; c = c.right) hi.push(c); }
    }
    return 0;
}

Common Nodes in Two BST

open on Scaler ↗

Return the sum of values present in both BSTs, mod 109+7, ideally in one pass.

Idea

Run two iterative inorder traversals at the same time (like merging two sorted arrays). Equal values → add to the sum and advance both; otherwise advance the side with the smaller value.

Pointers / traps

  • Advance only by popping and then moving to .right (the standard inorder step).
  • The HashSet approach (store tree A, look up tree B's values) also passes, at O(n) extra space.
  • Take the sum mod 109+7.
Java solution O(n + m) · O(h₁ + h₂)
public int solve(TreeNode A, TreeNode B) {
    Deque<TreeNode> s1 = new ArrayDeque<>(), s2 = new ArrayDeque<>();
    long sum = 0;
    TreeNode a = A, b = B;
    while ((a != null || !s1.isEmpty()) && (b != null || !s2.isEmpty())) {
        while (a != null) { s1.push(a); a = a.left; }
        while (b != null) { s2.push(b); b = b.left; }
        if (s1.peek().val == s2.peek().val) {
            sum = (sum + s1.peek().val) % 1_000_000_007L;
            a = s1.pop().right; b = s2.pop().right;
        } else if (s1.peek().val < s2.peek().val) a = s1.pop().right;
        else b = s2.pop().right;
    }
    return (int) sum;
}

BST nodes in a range

open on Scaler ↗

Count the nodes with B ≤ value ≤ C.

Idea

Prune using the BST property: node < B → search only the right subtree; node > C → search only the left; otherwise count the node and search both sides.

Pointers / traps

  • The range is inclusive.
  • Visiting every node is O(n). Pruning is O(h + k).
Java solution O(h + k)
public int solve(TreeNode A, int B, int C) {
    if (A == null) return 0;
    if (A.val < B) return solve(A.right, B, C);
    if (A.val > C) return solve(A.left, B, C);
    return 1 + solve(A.left, B, C) + solve(A.right, B, C);
}
LAB 3 · Q4

Distance between Nodes of BST

open on Scaler ↗

Return the number of edges between keys B and C in a BST (up to 106 nodes).

Idea

Find the meeting node (the lowest common ancestor) as the split point: walk down from the root while both keys are on the same side. Then distance = depth(B below the LCA) + depth(C below the LCA).

Pointers / traps

  • Write everything iteratively. With 106 nodes, a skewed tree would overflow the Java stack.
  • If one key is the LCA itself, its depth below the LCA is 0 (the B = 2, C = 6 example).
  • General binary tree version: dist = depth(a) + depth(b) − 2·depth(lca).
Java solution O(h)
public int solve(TreeNode A, int B, int C) {
    TreeNode lca = A;
    while (true) {
        if (B < lca.val && C < lca.val) lca = lca.left;
        else if (B > lca.val && C > lca.val) lca = lca.right;
        else break;                                   // split point
    }
    return depth(lca, B) + depth(lca, C);
}
int depth(TreeNode from, int key) {
    int d = 0;
    while (from.val != key) { from = key < from.val ? from.left : from.right; d++; }
    return d;
}
